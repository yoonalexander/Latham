# Handy adoption review for Latham

Research date: 2026-10-31. Source-only inspection through the GitHub connector; no upstream code, executables, or models were installed or run.

## Recommendation

**Worth a bounded transcription-backend experiment. Adopt only if measurements justify it.** The strongest fit is the public `transcribe-cpp` library used by current Handy source, through its official TypeScript binding in an independently authored Latham child process. Incorporating the complete Handy desktop application would add considerable integration work for capabilities Latham already owns.

Following this review, the user selected eventual integration as a planned direction in [design section 6.1.1](../Latham_Design_Document.md#611-planned-handy-speech-integration). Implementation and acceptance have not started; the runtime, dependency lockfile, and default recognizer remain unchanged.

## Comparison with Latham's design and implementation

Review baseline: design v1.8, especially sections 1.2, 5.8, 6.1, 6.3, and 11; the implemented [speech provider](../packages/speech/src/providers.ts), [Voice controller](../apps/desktop/src/main/voice.ts), [hands-free controller](../apps/desktop/src/main/handsfree.ts), and [evaluation evidence](evaluation.md). The [current design](../Latham_Design_Document.md) adds the selected future plan in v1.9.

| Requirement | Fit and consequence |
|---|---|
| Fast local recognition | Persistent models and alternative ASR families are promising. Latham currently spawns `whisper-cli.exe` and loads weights for every completed utterance. This review does not isolate how much of its delay comes from loading versus inference. |
| Electron/TypeScript | Handy's Tauri/Rust application is a different shell. The engine's official Node binding is a much closer fit; Latham already targets Node 22 or newer. |
| Owned final utterances | The public engine API can return transcript data to Latham. Keep turn/session ownership in Latham; partial or engine-committed text must not independently authorize an action. |
| Bound dictation and verified actions | Handy's general paste-into-active-app workflow does not establish Latham's exact field, permission, revision, effect, or verification contracts. All insertion must continue through Latham's Chrome/Notepad controllers. |
| Stop during recognition or execution | Retain the independent local stop detector and physical controls. A busy, aborted, or crashed ASR worker must not block them; discard late results using existing generation/session checks. Changing command ASR does not fix the documented wake/stop recognition misses. |
| Local privacy | In-memory PCM is supported by the public library. Preserve explicit microphone activation, bounded audio, no raw-audio/transcript files or content logs, and no silent cloud fallback. A resident model does not require idle microphone capture. |
| Independent implementation | Design section 1.2 permits ordinary licensed libraries. A library dependency with an independently authored adapter fits that policy. Importing or porting Handy application code would require an explicit revision to the reference policy. |

### Is the apparent speed credible?

There is concrete reason to investigate. Latham's Phase 4 evidence records base.en medians of **4,040 ms at two threads** and **3,162 ms at four threads**, with sampled p95s of 4,443 and 3,504 ms. These were eight clean synthetic phrases on an **i7-1065G7 / 16 GB Windows laptop**, with other development checks running. Two threads are the current default. They are historical local measurements, not new runs or broad speech benchmarks. [Latham results](evaluation.md#phase-4-evidence--october-31-2026).

The engine publishes Parakeet Unified Q8 results of **712 ms CPU / 448 ms Vulkan** for an 11-second sample on a Ryzen 7 PRO 4750U. Those numbers are compute-only means over three iterations after warmup; the Vulkan rig uses a RADV driver, not this Windows laptop. They support the hypothesis of substantially faster transcription, but cannot establish a speedup here. The Q8 model is **731 MB**, compared with Latham's current approximately 142 MiB base.en weights; download size is not peak RAM usage. [Pinned model card and benchmark](https://github.com/handy-computer/transcribe.cpp/blob/f1dcd15858c4bbba87ca97862b4e448b2cf15b8f/docs/models/parakeet-unified-en-0.6b.md).

Latham hands-free currently also waits for about **0.8 seconds of trailing silence** before invoking ASR. Action routing, target decisions, execution, and verification add further time. Faster ASR alone therefore does not establish the design's p95 target of a verified known command within one second after speech ends. Start with warm batch recognition; evaluate live streaming separately if the delay after capture remains a problem. The library's streaming support and a model's specific buffering configuration are separate decisions. [Hands-free segmentation](phase4.md#session-and-failure-rules), [design targets](../Latham_Design_Document.md#11-quality-targets-and-evaluation).

## Integration options and effort

| Option | Effort / recommendation |
|---|---|
| Use Handy separately as a dictation app | Easy to try, but this does not integrate its recognition into Latham's command pipeline. |
| Launch Handy's headless WAV CLI | Low effort for existing synthetic test files. A poor product endpoint: file-based input and process startup per invocation miss Latham's memory-only and warm-model goals. |
| Use the public engine binding in a Latham-owned process | **Recommended experiment; moderate product integration.** Keeps the current shell and action pipeline while making model lifetime and failure recovery explicit. |
| Embed/fork Handy or depend on its internal worker | High integration and maintenance cost: application state, hotkeys, recording ownership, history/paste behavior, version coupling, and provenance policy. Not justified by the speech requirement. |

The recommended integration is a contained backend change, but it is more than adding an npm package:

1. Extend the strict provider settings/parser and setup UI with an explicit backend/model choice, preserving existing saved Whisper configurations. Preflight actual model format, language, capabilities, device, and provenance.
2. Add a child process that loads the model once, accepts bounded in-memory PCM, and returns transcript data. Convert existing PCM16 to the library's float32 format; serialize requests and keep borrowed buffers intact until completion. Give it no UI action or microphone authority. Define cancellation, deadline, exit, unloading, and late-result behavior independently of Handy's protocol.
3. Connect it at the existing `localTranscribe`/`Voice.finish` boundary so push-to-talk and hands-free share the backend. Preserve independent stop/wake processing and all downstream binding/permission checks. Keep the existing Whisper route as an explicit selection rather than a silent fallback.
4. Update build/package handling for the ESM binding, Koffi native addon, and Windows native library/backend files. Latham currently bundles main into CommonJS and packages `dist`; installing dependencies alone will not copy these runtime artifacts. Verify from the portable executable on a machine without development tooling. [Current build](../scripts/build.mjs), [packaging](../scripts/package-preview.mjs), [binding/package instructions](https://github.com/handy-computer/transcribe.cpp/blob/f1dcd15858c4bbba87ca97862b4e448b2cf15b8f/bindings/typescript/README.md).
5. Only after acceptance, update design section 6.1, the decision index's nonresident-ASR choice, model/dependency provenance, setup guidance, and measured evaluation results. No shell migration, planner change, or expansion of app permissions is needed for this experiment.

## Smallest useful validation before adoption

Compare the existing Whisper route with a persistent `transcribe-cpp` worker and one English Parakeet candidate, initially in batch mode. Parakeet Unified EN is a reasonable first candidate because it also leaves a documented streaming path; it is not yet a selected default. First replay the same eight fixtures, then test representative physical-microphone commands and dictation: names such as Latham, short commands, negation, punctuation, silence, background speech, and modest noise.

Measure cold loading separately from warm inference, median/p95 final-transcript delay, end-of-speech to verified action, peak memory, and CPU use while stop/wake detectors remain active. Begin with CPU; identify and measure any available Vulkan device separately. Exercise Stop during loading/inference, worker hangs/crashes, malformed or oversized output, field changes, stale results, restart, and packaged deployment. Do not treat an ASR-only speed test as an end-to-end action test.

Adoption should require a material repeatable reduction in warm command latency on this laptop, acceptable cold start and resident memory, representative recognition at least as useful as the current route, and no regression in cancellation, local-only behavior, field ownership, or packaged startup. **This review supports doing that experiment; it does not yet support replacing the default or promising Handy's demonstrated speed.**

## Architecture and actual streaming

Handy is a Tauri/Rust desktop application with a web frontend. At release v0.9.8, it uses **transcribe-rs 0.3.8 with ONNX** for Parakeet and other ONNX engines, alongside **transcribe-cpp 0.2.4** for Whisper-family models. HEAD replaces that split with **transcribe-cpp 0.4.0 for every model**. [Release dependencies](https://github.com/cjpais/Handy/blob/14f6f0d31cb22a4268acfbddba3052820fd0a06e/src-tauri/Cargo.toml), [HEAD dependencies](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/Cargo.toml).

At HEAD, a child process owns the loaded native model and sessions; the desktop process supervises it. It is the Handy executable relaunched with an internal worker flag. Models remain loaded between requests until unload; the settings default is five idle minutes. This avoids per-utterance model initialization. This supervisor is absent from the inspected release tag. [Supervisor](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/engine_supervisor/mod.rs), [settings](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/settings.rs).

HEAD chooses three different behaviors from runtime capabilities: incremental decoding for streaming models; pause-based long-form chunks for eligible nonstreaming models; otherwise batch decoding after recording stops. The streaming path feeds audio as it arrives and emits separate committed and tentative preview text. Failure or empty output can trigger a whole-recording batch retry. Chunking during recording is not equivalent to a native streaming recognizer. [Policy](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/managers/transcription/policy.rs), [live sessions](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/managers/transcription/live.rs).

Model identity matters: HEAD's catalog marks **Parakeet Unified EN 0.6B** streaming, but **Parakeet TDT v3** and **Whisper** nonstreaming. Parakeet Unified uses buffered streaming; the engine documents a default lookahead of 2.08 seconds, with lower-latency configurations trading accuracy. Whisper uses internal 30-second windows. The release's live path explicitly falls back to batch for its ONNX engines, including its ordinary Parakeet path. [HEAD catalog](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/catalog/catalog.json), [engine Parakeet](https://github.com/handy-computer/transcribe.cpp/blob/f1dcd15858c4bbba87ca97862b4e448b2cf15b8f/docs/models/parakeet.md), [engine Whisper](https://github.com/handy-computer/transcribe.cpp/blob/f1dcd15858c4bbba87ca97862b4e448b2cf15b8f/docs/models/whisper.md), [release live path](https://github.com/cjpais/Handy/blob/14f6f0d31cb22a4268acfbddba3052820fd0a06e/src-tauri/src/managers/transcription.rs).

## Windows and integration

At HEAD, Windows x64 enables Vulkan and dynamically loaded CPU/backend modules; Windows ARM64 uses static CPU-only inference. The release's ONNX path is CPU-only on Windows; its manifest explains removal of experimental DirectML and an incompatible prebuilt runtime CPU baseline. HEAD stages native DLLs and app-local MSVC runtime libraries and includes packaging checks; missing modules, driver compatibility, and architecture still require packaged-machine validation. [HEAD Cargo](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/Cargo.toml), [release Cargo](https://github.com/cjpais/Handy/blob/14f6f0d31cb22a4268acfbddba3052820fd0a06e/src-tauri/Cargo.toml), [build staging](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/build.rs), [packaging workflow](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/.github/workflows/build.yml).

Both inspected Handy versions expose a headless **file batch** CLI: 16 kHz mono PCM WAV, installed model selection, JSON output, repeats, and device listing/selection. It loads once per invocation and reports loading separately from transcription. Remote toggle/cancel flags control the desktop application. Neither is a documented persistent, memory-only transcription service. HEAD's framed stdin/stdout worker protocol is internal, has no protocol version/negotiation field, and embeds engine types; treating it as a stable external API would couple Latham to Handy internals. [Release CLI](https://github.com/cjpais/Handy/blob/14f6f0d31cb22a4268acfbddba3052820fd0a06e/src-tauri/src/cli.rs), [HEAD headless implementation](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/lib.rs), [internal protocol](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/engine_supervisor/protocol.rs).

The reusable public library is **[handy-computer/transcribe.cpp](https://github.com/handy-computer/transcribe.cpp)**. Its v0.4.0 tag resolves to `f1dcd15858c4bbba87ca97862b4e448b2cf15b8f`. Official Rust and TypeScript bindings accept in-memory 16 kHz float PCM and retain models/sessions, including feed/finalize streaming. The TypeScript binding targets Node 22+, uses asynchronous native calls, and documents Electron packaging outside ASAR. This supports an independently authored Latham worker without importing Handy application code. It still needs a compatibility spike: one model permits one concurrent compute operation, PCM buffers remain borrowed until completion, and native faults require process isolation for robust recovery. [TypeScript binding](https://github.com/handy-computer/transcribe.cpp/blob/f1dcd15858c4bbba87ca97862b4e448b2cf15b8f/bindings/typescript/README.md), [Rust binding](https://github.com/handy-computer/transcribe.cpp/blob/f1dcd15858c4bbba87ca97862b4e448b2cf15b8f/bindings/rust/transcribe-cpp/README.md).

## Licensing, reliability, and evidence limits

Handy and transcribe.cpp declare MIT; Handy explicitly reserves its branding. Engine notices cover vendored ggml, miniz, and Silero code. Models have separate licenses: HEAD's catalog declares CC-BY-4.0 for Parakeet Unified/TDT v3 and Apache-2.0 for its converted Whisper entries. These are catalog declarations, not a completed redistribution audit; verify the exact pinned model card, source checkpoint, conversion attribution, and notices before shipping. [Handy license/branding](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/README.md#license), [engine notices](https://github.com/handy-computer/transcribe.cpp/blob/f1dcd15858c4bbba87ca97862b4e448b2cf15b8f/THIRD-PARTY-LICENSES.md), [model declarations](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/catalog/catalog.json).

HEAD isolates crashes/hangs, enforces timeouts, supports cancellation by terminating the worker, and retries certain GPU failures in CPU-only workers. Its fault-injection/model recovery tests include ignored tests requiring real fixtures; source presence does not establish successful execution here. [Supervisor and tests](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/engine_supervisor/supervisor.rs).

No speed, accuracy, memory, GPU compatibility, or release-binary behavior was measured in this review. The catalog's scores derive from specific datasets and a Ryzen 4750U CPU/Vulkan machine; its UI bars transform those results. Handy's CLI reports the fastest repeated inference and excludes model loading from that number. Neither establishes Latham's end-of-speech latency on this laptop or handles capture/VAD/paste overhead. A local comparison needs cold/warm timing, median/tail latency, actual device, representative speech accuracy, silence/noise, cancellation, and packaged restart recovery. [Catalog methodology](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/catalog/catalog.json), [score transforms](https://github.com/cjpais/Handy/blob/7bfb2e2c934b798bcf6e3627653aed2439996f89/src-tauri/src/catalog/mod.rs).
